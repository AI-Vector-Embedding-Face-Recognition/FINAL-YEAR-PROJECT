About this project

A face recognition attendance system built on vector embeddings. The camera, the face model and the data store all run in your browser.

What is a vector embedding?

It turns something complex, like a face, into a list of numbers. This system uses 128 numbers per face, for example [0.12, -0.45, 0.78, ...].

Two photos of the same person give vectors that are close together. Different people give vectors that are far apart.

Why not compare pixels?

Light, shadows, angle and image quality change pixel values a lot. The embedding keeps the facial pattern and ignores most of that noise.

How two faces are compared

Euclidean distance (used to decide)

d(A,B) = sqrt( sum (ai - bi)2 )

Straight-line distance between two vectors. Smaller means more similar. A match needs distance below the threshold (default 0.50, adjustable in Admin).

Cosine similarity (shown for information)

cos = (A · B) / (|A| |B|)

Compares the angle between vectors. Close to 1 means very similar direction. The best threshold must be found by testing with your own data.

Attendance flow

Camera → detect face → quality check → 128-D embedding → compare with saved vectors → threshold + margin check → same person on 2 scans → save name, session, date, time

  • Quality check: blurry, tiny or dim faces are rejected instead of guessed.
  • Margin check: if two people are almost equally close, the system says "not sure".
  • Two scans in a row: the same person must be matched twice to reduce false positives.
  • 2D map: PCA squashes 128 numbers to 2, so you can see the clusters on the 2D Lab page.

Privacy

Face vectors are personal biometric data. Here they are stored only in this browser and never uploaded. A printed photo or a phone screen can fool simple face recognition, so for real exams or payments add a liveness check and a server. Always get permission before registering someone's face, and delete data you no longer need from the Admin page.
